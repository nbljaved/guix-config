* Read this first
** What this does
It wipes =/dev/nvme0n1p3=, which holds =/=, =/home=, =/gnu=, =/nix= and =/swapfile=. It then reinstalls Guix System from your =guix-config= repo and restores your data and repos.

The EFI partition (=nvme0n1p1=, UUID =9591-0188=) and the swap partition (=nvme0n1p2=, UUID =27b860cf-…=) are *kept as-is*, so their UUIDs in =config-pc.scm= stay valid.

| Phase | Where                       | What                                              | Time          |
|-------+-----------------------------+---------------------------------------------------+---------------|
| [[*Phase 1 — Save everything (current system)][1]]     | current system              | commit/push, encrypted backups, prep config, USB | 1–2 h, hands-on |
| [[*Phase 2 — Install from the live USB][2]]     | live USB                    | format =nvme0n1p3=, install                        | 1–2 h, mostly waiting |
| [[*Phase 3 — First boot and restore][3]]     | new system                  | passwords, keys, repos, profiles, data            | 1–3 h         |

** Why a reinstall fixes the problem
Your daemon is running guix =520785e= from 2026-03-09, which is *unpatched* against the July 2026 =guix substitute= vulnerabilities. Upgrading it without substitutes failed because of the unprivileged daemon. The fix is to install from an ISO whose daemon is *already patched*. Substitutes are then safe from the very first minute, and nothing has to be built from source.

|                        | Release ISO 1.5.0 (signed)  | Development ISO (*use this one*)                        |
|------------------------+-----------------------------+---------------------------------------------------------|
| guix-daemon inside     | predates the fix: vulnerable | =64d4de2= (2026-08-17): security fix + July-5 regression fix |
| Substitutes during install | unsafe                  | safe                                                    |
| Integrity check        | GPG signature               | HTTPS from =ci.guix.gnu.org= only (see below)           |

- ISO used for this plan: CI build =24925386=, finished 2026-08-27, built from channel commit =e42227e= (2026-08-26). File size is =1308991488= bytes. Download: https://ci.guix.gnu.org/download/3964
- Always-latest link: https://ci.guix.gnu.org/search/latest/ISO-9660?query=spec:images+status:success+system:x86_64-linux+image.iso
  If that link now points to a newer build, that is fine. Any ISO built from a commit dated after 2026-07-05 contains both fixes, and step [[*2.4 Verify the ISO is patched — STOP if not][2.4]] confirms it on the machine itself.
- *Integrity, honestly:* development ISOs are not GPG-signed, and neither build farm publishes a signed hash for them. Your trust rests on HTTPS to =ci.guix.gnu.org=. That's the same party whose signing key you already trust for every substitute. The signed 1.5.0 ISO is verifiable, but it would put you back on a vulnerable daemon, so it's the worse option.
- An installed system defaults to =privileged? #t=, because "unprivileged is the default only on distros other than Guix System" (from the advisory). You make that choice explicitly in [[*D1 — daemon mode after the reinstall][D1]].

** The cheaper alternative (no reinstall)
Only if you change your mind:
1. =sudo reboot=. The daemon comes up privileged with substitutes disabled, which is consistent and safe.
2. =guix pull --no-channel-files --no-substitutes= takes hours. =python-minimal= passes now, because privileged builds get real UIDs.
3. =guix pull --no-substitutes= pulls your full channel set, since the config needs nonguix.
4. The final =reconfigure=: either build everything from source (very long, kernel included), or hand-run the freshly pulled =~/.config/guix/current/bin/guix-daemon= (its =GUIX= points to the patched substituter) and use substitutes. The second route is fiddly.
5. Revert the TEMP lines, reconfigure, reboot.

The reinstall trades those unattended hours, and the fiddly step 4, for about 1–2 h of careful backup work.

* Decisions to make before starting
** D1 — daemon mode after the reinstall
- *Privileged (recommended; it's the Guix System default).* Just delete the =privileged?= line. Builds run as the =guixbuild= users, like on the build farm, so =--no-substitutes= builds work. That is exactly your fallback the next time an advisory lands.
- *Unprivileged* =(privileged? #f)= is what you chose before, and it's a legitimate choice. The daemon doesn't run as root. But it *owns* =/gnu/store=, so a compromised daemon can already alter every binary you run, and the real gain is smaller than it looks. The cost: anything built locally may fail its test suite, because =chown= to an unmapped UID returns EINVAL instead of EPERM. Python, coreutils, Go and tar are known to hit this. That is exactly what blocked you. With a patched daemon, substitutes make local builds rare.
- *Either way:* remove =(use-substitutes? #f)=.

** D2 — disk layout
- *A (recommended):* keep the partition table. Reformat only =nvme0n1p3= with the label =guix-root=.
- *B (optional):* split =nvme0n1p3= into root (~350 GiB) and a separate =/home= (the rest), so the next reinstall can leave =/home= untouched. It adds steps in [[*2.5 Partition and format — DESTRUCTIVE][2.5]] and one =file-system= entry.

** D3 — backup medium
- An external drive with at least *20 GB* free. The home archive is roughly 12–15 GB before compression.
- One *age passphrase* protects both archives. The archives contain your SSH and age private keys. *Write the passphrase on paper.* Without it the backup is useless.
- If the drive is FAT32 (=vfat= in =df -T=), no single file can exceed 4 GiB. Use the =split= variant in [[*1.6 Back up home (encrypted)][1.6]].
- *Don't copy the T460's choice here.* The T460 ran with no backup at all (its D8), and that was nearly free because this machine still held a second copy of everything. Nothing holds a second copy of *this* machine: =~/.age/key= (which decrypts the diary), =~/.claude= 258M, =~/.librewolf= 1.1G, =~/.telega= 369M, Chrome's profile, =~/Calibre Library=, =~/Downloads/brilliant-cv= and the loose files in =~= all exist only here. The full survey is in =REINSTALL-thinkpad.org=, Appendix F.

** D4 — network during the install
- Plug an *Ethernet cable* into the onboard port. The installer can't use your Wi-Fi.
- Fallback: *USB tethering* from your phone shows up as =usb0= or =enp…u…=.

Rescuing a stash — option A keeps it on the remote as a branch. Commit your normal work first so the working tree is clean:
#+begin_src sh
git stash list
git stash show -p 'stash@{0}' | less
git stash branch rescue/stash-0 'stash@{0}'      # new branch, stash applied and dropped
git add -A && git commit -m "rescued stash: <message>" && git push -u origin rescue/stash-0
git switch -                                     # back to your branch; repeat with stash@{0} for the next one
#+end_src

Option B exports every stash as a patch into =$HOME=, where the backup picks it up:
#+begin_src sh
r=$(basename "$PWD"); n=$(git stash list | wc -l)
for i in $(seq 0 $((n-1))); do git stash show -p "stash@{$i}" > "$HOME/stash-$r-$i.patch"; done
#+end_src

** 2.7 Swapfile and hibernation offset
The recipe comes from the Guix manual's "Swap Space" section.
#+begin_src sh
dd if=/dev/zero of=/mnt/swapfile bs=1MiB count=16384 status=progress
chmod 600 /mnt/swapfile && mkswap /mnt/swapfile && swapon /mnt/swapfile
OFF=$(filefrag -e /mnt/swapfile | grep '^ *0:' | cut -d: -f3 | cut -d. -f1 | tr -d ' ')
echo "resume_offset=$OFF"          # a number; used in 2.8
#+end_src

** C. At-risk survey script
Save it as =~/repo-risk.sh= and run it with =bash ~/repo-risk.sh=. It's read-only.
#+begin_src sh
#!/usr/bin/env bash
# repo-risk: every git repo under $HOME and what would be lost if $HOME vanished.
cd "$HOME" || exit 1
find . \( -path ./.cache -o -path ./.local/share/containers -o -path ./.local/share/Trash \
          -o -path ./.emacs.d/elpaca -o -path ./.cargo -o -path ./.rustup -o -path ./go/pkg \
          -o -name node_modules \) -prune \
       -o -name .git -print 2>/dev/null | sed 's#^\./##; s#/\.git$##' | sort |
while read -r r; do
  cd "$HOME/$r" || continue
  out=""
  [ -z "$(git remote 2>/dev/null)" ] && out+=" NO-REMOTE"
  n=$(git status --porcelain 2>/dev/null | wc -l);   [ "$n" -gt 0 ] && out+=" uncommitted:$n"
  s=$(git stash list 2>/dev/null | wc -l);           [ "$s" -gt 0 ] && out+=" stashes:$s"
  u=$(git rev-list --count --branches --not --remotes 2>/dev/null)
  [ "${u:-0}" -gt 0 ] && out+=" unpushed-commits:$u"
  printf '%-62s %s\n' "$r" "${out:- ok}"
done
#+end_src

** D. Troubleshooting
- *No network in the installer:* Wi-Fi is expected to fail. Check the cable and =ip -br link=, and try =dhcpcd= on the right interface, or phone tethering.
- *Black screen on the ISO:* at GRUB press =e= and add =nomodeset= to the =linux= line.
- *=guix system init= builds the kernel or firmware from source:* the nonguix key isn't authorized, or =$SUBS= was lost (new shell). Re-run the =guix archive --authorize= line and =SUBS=…, then init again.
- *"no file system with label guix-root":* check =e2label /dev/nvme0n1p3=. The label must match the config exactly.
- *"no such file: signing-key.pub":* it must sit next to whichever config file you pass. See 2.8.
- *Tests fail with =OSError: [Errno 22] Invalid argument= / chown:* you're building from source on an *unprivileged* daemon. Use substitutes, or switch D1 to privileged.
- *Swap partition missing at boot:* you ran =mkswap= on =p2= and its UUID changed. Update the =27b860cf-…= UUID from =blkid=.
- *Hibernation doesn't resume:* =resume_offset= is wrong. Recompute it with the 2.7 command (on the running system: =sudo filefrag -e /swapfile=), then reconfigure.
- *Machine boots into the old GRUB entry, or no entry:* boot the USB, mount as in 2.6, and re-run 2.10. Or inspect with =efibootmgr -v=.
- *=sudo guix system reconfigure= says =linux: unbound variable=:* that's the system guix without nonguix. Use the command at the end of 3.7.
